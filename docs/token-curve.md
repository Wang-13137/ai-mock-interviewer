## 怎么读这张表（也是面试要点）

1. **压缩有触发点，不是全程平滑受益**。预算 3000 token 在第 25 轮才被击穿，
   此前两臂 token 几乎相同（第 20 轮甚至略高，因为摘要注入本身占两位 participant 位）。
   所以「省 token」只在长会话里兑现，短会话反而多一次摘要调用。
2. **代价在延迟**：触发摘要的那几轮端到端从 ~3 s 涨到 ~17 s（多一次摘要 LLM 调用）。
   这是典型的「成本 vs 延迟」权衡，可以做异步摘要或缓存来优化。
3. 预算取 3000 是因为本机模型的常见上下文够用；换模型/换 prompt 要重新标，
   同一份评测思路见 `scripts/token_curve.py`。

## 复现

```bash
AIMI_LLM__PROVIDER=zhipu AIMI_LLM__API_KEY=<key> python scripts/token_curve.py --turns 30
```
